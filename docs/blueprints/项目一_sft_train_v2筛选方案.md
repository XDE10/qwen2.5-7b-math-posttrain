## 1. 决策

建议优先验收 coverage 候选：回答 500～3000 tokens，完整上下文不超过 3800，SFT 窗口 4096；若 A100 完整更新与 dev pilot 通过，再将项目一所有核心比较组的 RL/主评测回答预算统一冻结为 3072。3000 与 3072 之间的余量仅是参考轨迹长度余量，不保证模型生成不截断。

资源不足时采用 balanced 候选：回答 500～2200，RL/主评测统一 2560。若必须维持 RL 2048，保留原 1500 条紧凑版作为历史基线，或另建 compact 分层版；本次相同题型配额只能选出 1448 条，不补重复、不悄悄改配额。以上是待验收的三档方案，不要求三档都跑完整训练。

选择 coverage 的依据是几何、数论覆盖和来源多样性的候选空间，而不是已证明更高准确率。不选择 3200 作为主版，是为了避免参考回答超过拟议 RL 3072 预算；它只用于统计上界。现有项目二数学 1024、代码 1536 预算不受此决定影响。

## 2. 全量统计说明了什么

固定 OpenR1 revision `e4e141ec9dea9f8326f4d347be56105859b2bd68` 的 default/train 共 93733 行，不是按数据集名字推断的 220000 行；归并后为 93536 道唯一题。193767 条原始轨迹中，重复轨迹只算一次独立观测。28627 行的源 `correctness_count` 与逐轨迹 math-verify 计数不一致，故必须用对齐的列表重新计算。

在源标记完整正确的每题最短轨迹中，Geometry 回答中位数 5410，Number Theory 4786，Combinatorics 5133.5 tokens。额外无启发式告警后，中位数分别为 2986、2630、2120。这是过滤后总体发生变化，不是过滤器把长推理“压缩”了，也不能把留下的轨迹直接当成高质量金标。

回答上限 1600/2200/3000/3200，在完整上下文≤3800、质量门槛与既有去重规则下，分别保留 4870/10927/18050/19393 道候选。对应全池监督 token 为 6172509/17710238/36115530/40279500，不能把全池 token 当成最终 1500 条的训练成本。

重点分支的保留量：

- Geometry：483 → 1118 → 2023 → 2258。
- Number Theory：520 → 1414 → 2560 → 2763。
- Combinatorics：584 → 1152 → 1688 → 1768。

放宽长度后，代数仍占大头。因此仅放宽上限仍不能解决题型偏向，必须显式分层抽样。完整的 source、problem_type、通过率分组 P50/P75/P90（回答与完整模板长度）、各题型双分母保留率和监督 token 总量见 [统计与试选证据](<../reports/project1_sft_v2_plan_20261023/统计与试选证据.md>)。

## 3. 可执行的题型与采样规则

1500 条的起始配额：Algebra 525，Geometry 300，Number Theory 300，Combinatorics 225，Inequalities 100，Logic and Puzzles 50。它将几何、数论、组合合计提升到 55%，代数为 35%；这是一组预先声明的覆盖策略，不是从测试集频数拟合的最优比例。

OpenR1 分类不等于 MATH 分类：Algebra 内仍需审核代数、初等代数、中级代数、预备微积分等细分；Combinatorics 还需审核是否覆盖概率；Logic and Puzzles 并不自动等于 GSM8K 应用题。Calculus、Other、mixed 在本轮主配额外，保留在候选池用于后续审核，不宣称由上述配额就覆盖所有评测分支。真正的 GSM8K 能力保持由冻结 dev 方案与最终测试检验；若需补充应用题，另立 train 数据版本和配对对照。

每题仅选择一条：字段逐索引对齐 → 完整、math-verify=true、正常结束且最终答案结构完整 → 无质量拒绝/待审信号 → 回答与总长度合格 → 在合格轨迹内择最短，以文本哈希打破同长平局。不截断或改写回答后继承旧验证标签。

题目在每个题型内以固定盐 `sft-v2-proposal-42/` 加 question hash 排序，避免全局按长度排序只选最短题，也避免源文件先到先得。每题型优先分配约 15% 给源教师验证通过率在 (0,1) 的题，剩余按哈希顺序补齐同题型；不足时记录代理配额缺口，不称为真实难度不足或自动改成其他题型。15% 是多样性设计参数，既不是“难题占比”，也不是效果结论。

长度比例由试选产生，不预设 70%/30%。后续若对长度比例再做控制，必须另立版本并解释新增选择偏差。

## 4. 实际试选结果与成本

三档只导出题目哈希、源位置、轨迹哈希、长度、代理指标和待审状态；文件名含 proposal，不含完整答案，不可直接当作训练 JSONL。

- compact：1448 条，1846633 个监督 token，全部≤1600；Inequalities 仅有 48/100 条，明确缺 52 条。相同配额不可行，不重新分配掩盖缺口。
- balanced：1500 条，2462686 个监督 token；≤1600 为 638 条，1601～2200 为 862 条。全部缺少可信 Level 标签。
- coverage：1500 条，3030469 个监督 token；≤1600 为 398 条，1601～2200 为 499 条，2201～3000 为 603 条。仅 3 条关联 Level 5、1 条关联 Level 3，其余 1496 条未知。

coverage 每 epoch 的监督 token 比 balanced 多约 23.1%。同 epoch、同条数不等于同训练成本；同时报告监督 token、题目曝光、更新数、实际 GPU 时间。数据版本效果比较需单独设计等监督 token 的配对对照，不能把数据/长度/额外训练量混为一个算法收益。E3/E4 的算法比较必须共用同一版 E1，不中途切换 SFT 数据。

逐题索引与统计见 [机器可读汇总](<../reports/project1_sft_v2_plan_20261023/summary.json>)、[coverage 试选](<../reports/project1_sft_v2_plan_20261023/coverage_proposal.json>)、[balanced 试选](<../reports/project1_sft_v2_plan_20261023/balanced_proposal.json>)。试选不是封存成品。

## 5. 难度和质量：正式导出前的硬缺口

**不能验收“已保证 Level 3～5 中高难度占比”。** 整个≤3200 候选池只有 24 道可精确关联 MATH train Level，coverage 试选仅有 4 道。source 和源教师几次采样的通过比例只能作为代理；不能从 MATH-500 回填难度，也不能读取测试成绩反向调整配额。

后续按两条轨道补证据：

1. 本地：对 coverage 分层抽至少 100 条过程审核，覆盖每个题型、三个长度桶、来源和通过率分组；所有可信 Level 关联题与可疑轨迹额外全审。逐项记录题意、最终答案、关键推导、是否漏条件、是否缺图、分支标签、难度判断依据和审核者。未审核字段保留 pending；不得自动填“通过”。
2. 上卡：在 train 候选池用原始 7B、统一提示/温度/预算做可解性诊断，保留采样次数与不确定性。需要提高中高难覆盖时，只从训练候选补样；其模型通过率标签与 MATH Level 分开。先做小样本评估吞吐，再决定扩大，不预承诺全量成本。

若必须在上卡前取得可信 Level 3～5 配额，可在独立版本中补充有真实等级的 MATH train 题，并通过盲生成/独立验证得到完整解答；这是新增来源实验，不静默混入当前 OpenR1-only 方案。本轮没有生成这些解答。

当前噪声规则可自动拒绝控制字符、明确复读等；`many_restarts_not_proven_incoherent` 是待复核信号，记录了 74558 次轨迹告警，不能等同 74558 道坏题。抽样复核应另外覆盖至少 50 条被此规则拦下的轨迹，检查回溯是否合理；若误杀明显，只在 train 规则开发集修订，再重建全量统计与新版本试选。不要单纯为了凑题取消质量门槛。

源 math-verify=true 不是本地独立重验，更不是过程正确证明。正式导出时回放源 parquet，核验题面与轨迹 SHA，固定独立判分器版本；不支持的数学对象进入隔离/复核，不能默认为错误或正确。审核发现明显推理错误时剔除并回填同层候选；抽样无错也只代表抽查范围，不能宣称逐条金标。
