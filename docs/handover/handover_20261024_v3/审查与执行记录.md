## 审查结论

**可以采用“宁可排除可疑题”的保守策略，并优先采用equal_exposure作为SFT主对照。Gemini给出的纯净性与筛选数量保证不成立，需要修正。**

1. “172+8”必须先按RL侧唯一ID求并集，不能直接把匹配对数当题数。本轮核对：留出集侧172个RL ID，SFT侧8个RL ID，交集为空，最终确为180题。这个结果是实际核对成立，不是对其他报告也成立的加法规则。
2. Jaccard≥0.50是复核信号，不证明每题都是真重复。本次依据用户“不逐题挽留”的偏好保守排除，不能将被排除的180题全部标成数学错误或已证实污染。
3. 剩余4630题不能叫“纯净池”。只能说对同一规范化、字符5gram、阈值0.50及同一批对照文件复查为零命中。embedding/同构语义、源质量和基础模型预训练污染仍未验证。
4. 4630题不保证筛出3000题；至少约64.8%的候选须同时满足完整可评分与8次rollout经验通过率25%～75%条件。当前7B通过率与评分器支持率都未知，不能提前保证最终数量。
5. equal_exposure无需等token停止器。它可以独立冻结研究参数；CPU通过和参数冻结仍不等于Colab/GPU验收或正式运行放行。SFT冻结也不代表E2～E4或正式RL池已冻结。
