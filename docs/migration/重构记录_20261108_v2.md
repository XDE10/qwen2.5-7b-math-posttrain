# 目录重构记录 v2（2026-11-08）

> 本文件记录「把仓库整理成同类项目结构」这次**目录重整**的动机、决策、统计与遗留事项。
> 注意区分：[重构记录_20261108.md](重构记录_20261108.md) 只记录更早的**文档层移动**（`project_blueprints → docs/blueprints` 等），不是本次 v2 重整。

## 动机

- 仓库根目录长期混入 v1…v92 各代脚本、测试、配置与报告：`scripts/` 140 个文件、`tools/` 63 个、`tests/` 95 个、`src/` 75 个、`reports/` 70 个报告目录，无法一眼判断什么是现行主线。
- 旧 README 的目录结构表与代码地图已过时（仍引用 `scripts/train_project1_sft.py` 等旧路径）。
- 用户目标：目录要像同类项目一样规整。选择**彻底重整**：现行主线留在顶层，历史版本统一移入 `archive/`，不删除任何文件，并保持 pytest 基线可比。

## 决策

1. **keep 判定规则**：从活跃入口出发的**导入闭包** + **文档明确引用**的代码/配置/数据留在顶层；其余全部归档。
2. **现行主线保持原相对结构**（`scripts/training/`、`scripts/evaluation/`、`src/{data,evaluation,losses,training}/`、`tools/{aimo,evaluation,qfft,review,verification}/`），只做「分层 + 归档」，减少导入与测试改动。
3. **归档保持「类别 + 原相对路径」**（`archive/{configs,scripts,tools,src,tests,experiments}/`）；`archive/reports/` 额外按 `YYYY-MM-DD` 分桶，88 个原先散落在 `reports/` 根下的 log/json/md 进入 `archive/reports/_loose/{logs,audits,snapshots}/`（实测 87 个文件）。
4. **不删除任何文件**：本次 570 次移动、0 删除；未被 git 跟踪的历史文件移动后仍不入库。
5. **大体积数据/证据/报告只在本地**：`.gitignore` 忽略 `data/`、`artifacts/`、`reports/`、`archive/data/`、`archive/reports/`、`.pilot_deps/`、`*.zip`、`.pytest_tmp/`（各目录保留 README 例外）；git 只跟踪代码、配置、文档与 archive 中的代码/测试/配置快照。
6. **映射与重放**：每次移动都写入 mapping JSON，保留可重放脚本与 pytest 基线，便于核对与回退。
